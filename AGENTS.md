# Правила разработки в этом репозитории

## Что это

`s-generate` — браузерный генератор процедурной графики: грибы, деревья, кустарники,
холмы, облака, горы. Один движок выводит либо **плашку** (объект + рамка + подпись),
либо **сцену** (ландшафт). Всё строится из сида, рисуется в Canvas 2D и
экспортируется в PNG; в перспективе — анимированный GIF.

Проект учебно-развлекательный: ценность в процессе, а не в продукте.
План не конечный — он живёт в [docs/PLAN.md](docs/PLAN.md) и меняется по мере интереса.

## Жёсткие ограничения

1. **Только Canvas 2D.** Никакого WebGL/WebGPU, three.js, SVG-рендера, CSS-градиентов
   вместо рисунка. Объём имитируется проекцией, сортировкой по глубине и затенением
   полигонов.
2. **0 зависимостей.** В `package.json` нет `dependencies` и `devDependencies`. Node
   используется только для `node --test` и статического сервера, и только со
   встроенными модулями. Новая зависимость = отдельная запись в
   [docs/DECISIONS.md](docs/DECISIONS.md).
3. **Только нативные ES-модули.** `<script type="module">`, импорты с явным `.js`,
   никакого бандлера и транспиляции. Приложение открывается статическим сервером
   «как есть».
4. **Детерминизм.** В `src/` нет `Math.random()`, `Date.now()`, `performance.now()`.
   Случайность — только из `core/rng.js`; сид — строка, превращаемая в `uint32`.
5. **Никаких бинарных ассетов.** Ни PNG, ни шрифтов, ни моделей, ни иконок. Всё
   видимое вычисляется кодом. Исключение — скриншоты в `docs/shots/`.
6. **Никаких сетевых вызовов в рантайме.** Ни CDN, ни API, ни веб-шрифтов. После
   загрузки статики приложение работает офлайн.
7. **Никаких ключей и бэкенда.** Экспорт PNG/GIF — целиком на клиенте.
8. **Один объект — один сид.** Сид объекта не зависит от соседей: добавление нового
   гриба в сцену не должно менять остальные.

Если задача требует нарушить пункт 1–8 — не ломай правило молча: предложи изменение
и зафиксируй его в `docs/DECISIONS.md`.

## Слои и ответственность

| Каталог | Можно | Нельзя |
|---|---|---|
| `src/core/` | RNG, математика, сплайны, шум, палитры — чистые функции | DOM, canvas, глобальное состояние |
| `src/model/` | Генераторы форм (гриб, дерево, гора…), имена, параметры | DOM, canvas, сеть |
| `src/scene/` | Композиция, размещение, коллизии, свет, атмосфера | Рисовать пиксели |
| `src/render/` | Display list → canvas, контур, зерно, рамка | Придумывать формы, тянуть RNG |
| `src/export/` | PNG, GIF, квантование, кадры | Менять сцену или её параметры |
| `src/ui/` | DOM, контролы, URL, скачивание, часы анимации | Считать геометрию |
| `src/app/` | Связывание слоёв, точка входа | Логика генерации |

Правило: `core/`, `model/`, `scene/` и построение display list импортируются в
`node --test` без браузера. Если модуль тянет DOM или canvas — он лежит не там.

## Детерминизм

* **Сид → RNG.** `hashSeed(seedString)` (FNV-1a) → `makeRng(seed)` (mulberry32).
* **Именованные потоки.** Каждая часть объекта берёт свой поток:
  `rngStream(seed, 'pileus')`, `rngStream(seed, 'spots')`. Тогда добавление юбки не
  сдвигает случайные числа шляпки.
* **Квантование.** `shade` — 4–6 ступеней, цвета — 8 бит на канал, координаты в
  хэше эталона — до 1/16 px. Всё, что сравнивается, сравнивается квантованным.
* **Стабильный порядок.** Сортировка по глубине при равных `z` падает на исходный
  индекс, а не на порядок `Array.sort` «как получится».
* **Golden-тесты** ловят расхождения. Если кадр изменился намеренно — обнови эталон
  и объясни причину в коммите.

## Изображение

* Стиль — гладкая иллюстрация: полигоны, квантованный свет, чернильный контур,
  лёгкое зерно. Пиксель-арт не цель.
* Сцена считается в логических единицах и **не зависит от `devicePixelRatio`**;
  масштаб применяется только при выводе.
* Палитра сцены — ≤ 24 базовых тонов. Новые цвета — через `core/palette.js`, не
  литералами по коду.
* Градиенты — только в атмосфере, небе и виньетке. Формы заливаются плоским цветом.
* Антиалиасинга «на глаз» нет: контуры 1–2 px в логических единицах, при экспорте
  масштабируются целым множителем.

## Анимация

* Модель статична. `t` влияет только на ветер, качание и циклы (дождь, птицы).
* Рендер — чистая функция `(scene, view, t) → display list`.
* Экспорт кадров — по равномерной сетке `t`, а не по реальному времени; поэтому
  GIF воспроизводим.

## Стиль кода

* 2 пробела, `;`, одинарные кавычки, `const` по умолчанию.
* Имена — английские, комментарии — русские и только про «почему».
* Только именованные экспорты: `export function buildMushroom() {}`, без `default`.
* JSDoc на экспортируемых функциях `core/`, `model/`, `render/`: типы входов/выходов.
* Файл — одна ответственность, до ~300 строк; больше — делить.
* Ошибки не глотать: чистые функции возвращают `{ok:false, reason}`, UI показывает
  причину.

## Git

* Ветка `main` — всегда рабочая. Работа — в `feat/…`, `fix/…`, `docs/…`, `chore/…`.
* Коммиты: `feat: …`, `fix: …`, `docs: …`, `refactor: …`, `test: …`, `chore: …`.
* Один коммит = одна логическая правка; сообщение объясняет «зачем».
* Перед пушем `npm test` зелёный.

## Проверки

```bash
npm start            # http://localhost:8080 — статический сервер, 0 зависимостей
npm test             # node --test: unit + golden display list
```

Обновление эталонов (только при намеренном изменении картинки):

```bash
# PowerShell
$env:UPDATE_GOLDEN=1; npm test
# bash
UPDATE_GOLDEN=1 npm test
```

Чеклист глазами перед PR: гриб крупным планом; плашка с рамкой и подписью; сцена с
холмами и облаками; лес из 5–9 деревьев; экспорт PNG 1080×1080; один и тот же сид
даёт один и тот же кадр после перезагрузки.

## Как добавить новый род

1. Описать анатомию и параметры в [docs/CONTENT.md](docs/CONTENT.md).
2. Добавить генератор в `src/model/` — чистая функция `build<Kind>(spec) → Model`.
3. Завести именованные RNG-потоки; параметры по умолчанию — в `spec`, не в коде.
4. Добавить палитру в `core/palette.js` (не hex-литералы в генераторе).
5. Golden-тест: один-два характерных сида + проверка «сид → тот же результат».
6. Проверить, что род работает и в плашке, и в сцене (масштаб, глубина, силуэт).
7. Обновить README и, если появилось новое правило, `AGENTS.md`.
