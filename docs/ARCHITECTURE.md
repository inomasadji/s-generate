# Архитектура

## Принцип

Одна сцена описывается данными и рисуется одним путём. Ни один генератор не знает
про canvas: он возвращает полигоны в локальных координатах. Всё, что нужно для
картинки, появляется на шаге сборки **display list** — плоского списка готовых к
заливке полигонов с цветом и глубиной. Растеризация — тонкий слой поверх
`CanvasRenderingContext2D`.

```
seed ──► spec ──► model ──► scene ──► display list ──► canvas
         (ui)     (model)   (scene)     (render)         (render/paint)
```

Каждая стрелка — чистая функция. Благодаря этому в `node --test` проверяется всё,
кроме последнего шага.

## Слои

| Слой | Вход | Выход | Зависит от |
|---|---|---|---|
| `core/rng` | строка сида | `() => number` в `[0,1)` | — |
| `core/spline` | точки, `t` | точки кривой | `core/math` |
| `core/noise` | `x, y` | `[-1, 1]` | `core/rng` (только для таблицы) |
| `core/palette` | имя темы | `[r,g,b]` | — |
| `model/*` | `spec` | `Model` (полигоны) | `core/*` |
| `scene/*` | `spec` | `Scene` (объекты + камера) | `model/*`, `core/*` |
| `render/build` | `Scene`, `view`, `t` | `DisplayList` | `core/*` |
| `render/paint` | `DisplayList`, `ctx` | пиксели | canvas |
| `export/*` | `Scene`, кадры | Blob / `Uint8Array` | `render/*` |

## Система координат

Мир: `x` — вправо, `y` — вверх, `z` — к зрителю. Единица — «рост гриба» ≈ 1.
Камера — ортографическая, с углами `yaw` (поворот вокруг `y`) и `pitch` (наклон).
Ортография, а не перспектива: так объекты не «разъезжаются» при смене размера
холста, а плашка и сцена используют один код.

```js
// render/camera.js
export function projectPoint(point, camera) {
  // 1. rotateY(yaw), rotateX(pitch)
  // 2. экран: sx = cx + v.x * scale, sy = cy - v.y * scale, depth = v.z
}
```

`scale` — пикселей на единицу мира; `cx, cy` — центр кадра. Никакой перспективы и
`devicePixelRatio` в модели.

## Модель объекта

```js
/**
 * @typedef {[number, number, number]} Vec3
 * @typedef {{ pts: Vec3[], color: [number, number, number],
 *             normal?: Vec3, group?: string, layer?: number,
 *             bias?: number }} Poly
 * @typedef {{ kind: string, seed: string, polys: Poly[],
 *             bounds: { min: Vec3, max: Vec3 } }} Model
 */
```

* `polys` — уже в локальных координатах объекта, порядок детерминирован.
* `group` — для отладки и адресных правок («pileus», «spots»).
* `layer` — очередь рисования внутри объекта: ножка `0`, шляпка `1`, пятна `2`.
  Это не физика, а договорённость: пятна всегда лежат на шляпке.
* `normal` считается один раз при сборке; нужен для света и контура.
* Библиотека не «склеивает» геометрии: merge — это `polys.push(...other.polys)`.

Объект, который всегда смотрит в камеру (листва, облако), — тот же `Poly`, но с
`pts` в плоскости `xy` и флагом `billboard: true`; при сборке к нему применяется
только трансляция, без поворота.

## Сцена

```js
/**
 * @typedef {{ mode: 'plate'|'scene', seed: string, palette: string,
 *             camera: {yaw: number, pitch: number, scale: number},
 *             light: Vec3, objects: Placed[], sky: object,
 *             layers: Layer[], plate?: {title: string, subtitle: string} }} Scene
 */
```

* **Плашка.** `scene/specimen.js` выбирает модель и школу имён по `kind`.
  Широкие роды (гора, холм, облако) получают небо внутри рамки и выравнивание
  по низу области рисунка: иначе объект висит в пустом прямоугольнике.
* **Сцена** — небо и земля фоном, рельеф готовыми экранными полигонами, объекты —
  моделями с позицией и масштабом.
* Сцена ничего не знает про размер холста: `scale` подбирается в `render`.

## Ландшафтная сцена

* **Фон** — два градиента: небо до горизонта и земля от горизонта вниз. Это
  единственное место, где градиенты разрешены.
* **Рельеф** — полигоны в логических координатах 720×720, без 3D:
  солнце, два горных хребта со снегом, облака, три плана холмов, трава.
* **Объекты** — модели из `model/`, спроецированные камерой и поставленные на
  землю: `{ model, x, y, scale }`. `y` — линия, на которой стоит объект.
* **Порядок.** Объекты сортируются по `y`, затем получают слой
  `10 + index * 10`. Внутри объекта прибавляется его собственный подслой
  (ствол 0, листва 1; ножка 0, юбка 1, шляпка 2, пятна 3). Так дальний объект
  рисуется целиком до ближнего, а контур не просвечивает сквозь шляпку.
* **Тени** — эллипсы слоя 5, под всеми объектами: без них предметы висят в воздухе.
* **Билборды.** Листва и облака — плоские диски в плоскости XY, а не сферы:
  при наклоне камеры 0.1–0.2 рад этого достаточно, а полигонов в разы меньше.

## Display list

```js
/**
 * @typedef {{ pts2d: [number, number][], color: string,
 *             z: number, stroke?: string, group?: string }} Item
 * @typedef {{ width: number, height: number, items: Item[],
 *             backdrop: object, overlay: object }} DisplayList
 */
```

Порядок `items` — уже отсортированный по `z` (дальние раньше), сортировка
стабильная: при равном `z` сравнивается исходный индекс. Хэш display list — это и
есть golden-эталон; пиксели для сравнения не нужны.

## Рендер

1. **Фон** — небо и градиенты (единственное место, где разрешены градиенты).
2. **Дальние слои** — горы, облака; цвет смешан с цветом неба на `haze`.
3. **Объекты** — слоями: ножка → шляпка → пятна. Внутри слоя полигоны идут от
   дальних к ближним.
4. **Контур** — рёбра силуэта: ребро, встречающееся один раз, — граница. Рисуется
   **до** заливки слоя и вдвое толще: заливка закрывает внутренние рёбра, снаружи
   остаётся половина линии. Иначе скрытые рёбра (дальний край шляпки) просвечивают
   сквозь объект.
5. **Атмосфера** — общая дымка, виньетка.
6. **Зерно** — тайл 256×256 из `ImageData`, `globalCompositeOperation = 'overlay'`,
   `alpha 0.05–0.12`. Тайл генерируется один раз из RNG с фиксированным сидом.
7. **Рамка и подпись** — только в `plate`; приходят из display list как `overlay`,
   чтобы не сортироваться вместе с полигонами.

## Свет и цвет

* Один направленный свет на сцену: `shade = max(0, n · l)` с ambient `0.35`.
* `shade` квантуется в 6 ступеней — так картинка выглядит «нарисованной», а не
  «отрендеренной», и стабильно хэшируется.
* Итоговый цвет = `palette[group] * shade`, затем лёгкий сдвиг оттенка в тень
  (холоднее) и в свет (теплее) — на 3–5 %.
* Палитра сцены — ≤ 24 базовых тонов; тема задаёт весь набор, генератор только
  выбирает индексы.

## Контур

Контур — не «обводка каждого полигона» (иначе видна сетка), а граница силуэта:

1. для объекта собрать все рёбра как пары округлённых вершин;
2. ребро с частотой 1 — внешнее;
3. нарисовать ломаные цветом `ink`, толщина `1–2` логических единицы.

Для мелких деталей (точки, пластинки) контур можно отключить флагом `outline: false`,
если он «зашумляет» силуэт.

## Сид и случайность

```js
// core/rng.js — контракт
export function hashSeed(text) {}      // FNV-1a → uint32
export function makeRng(seed) {}       // mulberry32 → () => [0,1)
export function rngStream(seed, name) {} // hashSeed(seed + ':' + name) → makeRng
export function range(rng, lo, hi) {}
export function pick(rng, list) {}
export function gauss(rng, mean, sd) {}
```

Правила:

* Ни один генератор не вызывает `Math.random()`.
* Каждая часть объекта — свой поток: `rngStream(seed, 'stipe')`,
  `rngStream(seed, 'pileus')`, `rngStream(seed, 'spots')`.
* Шум (Perlin) тоже детерминирован: таблица перестановок строится из RNG с сидом
  `seed + ':noise'`.
* Шум сэмплится в непрерывном домене (`t·cos a, t·sin a`), чтобы шляпка не рвалась.

## Имена

`model/naming/` — четыре школы, у каждой свой генератор и свой словарь:

| Файл | Род | Устройство |
|---|---|---|
| `naming.js` | гриб, дерево | слоги + латинское окончание |
| `celtic.js` | гора | гэльские префиксы (`Càrn`, `Sgùrr`) + эпитет |
| `slavic.js` | холм | прилагательное согласуется с родом существительного |
| `asian.js` | облако | 2–3 коротких слога без повторов |

Слаги — через `naming/slug.js`: кириллица и диакритика транслитерируются, чтобы
имя файла оставалось `[a-z0-9-]`.

Цепь Маркова (как в исходной статье) — возможное улучшение, но не обязательное:
слогов хватает, а данных на пару килобайт вместо матрицы.

## Размещение и коллизии

* `scene/place.js` — rejection sampling: до 200 попыток на объект.
* Проверка — по упрощённому силуэту: эллипс/прямоугольник в мировых координатах,
  а не по всем полигонам.
* Порядок объектов фиксирован сидом сцены; отказ от объекта не сдвигает остальные.

## Анимация

* `render/build(scene, view, t)` — `t` в секундах.
* Ветер: смещение вершин `dx = A(t) * weight(y) * sin(t * w + phase)`, где `phase`
  и `w` — из сида объекта. `weight` растёт с высотой: ствол стоит, верхушка качается.
* Модель не меняется, поэтому экспорт кадра `t = i * dt` воспроизводим.
* `prefers-reduced-motion` — `t = 0`.

## Производительность

* Бюджет: объект плашки ≤ 1500 полигонов, сцена ≤ 12000.
* `render/build` не должен выделять память в цикле: массивы переиспользуются.
* Замер — отдельный тест: 100 кадров сцены, порог в миллисекундах пишется в лог,
  падение больше чем в 2 раза от базового — повод разобраться.
* Экспорт может быть медленным: он офлайновый и делается один раз.

## Тесты

| Что | Как |
|---|---|
| RNG | один сид → одна последовательность; разные потоки независимы |
| Сплайн | концы совпадают с крайними точками, `t=0.5` внутри габаритов |
| Генератор | `buildMushroom` дважды → идентичный `polys` |
| Golden | хэш display list для 2–3 характерных сидов |
| Экспорт | первые байты PNG/GIF, размер, число кадров |
| Бюджет | число полигонов ≤ лимита |
